# تكامل ATLOS — إطلاق SOLO الرقمي

## كيف يعمل الدفع

ينشئ العميل المسجّل طلبًا رقميًا عبر `create_order_atomic`. يحسب الخادم السعر ويتحقق من المنتج والباقة والمخزون؛ ويبقى الطلب معلّقًا إلى أن يصل إشعار موثّق. لا تُعدّ رسائل نجاح واجهة المتصفح إثباتًا للدفع.

يتحقق `atlos-webhook` من توقيع HMAC-SHA256 على الجسم الخام، ثم يطابق التاجر والطلب والعملة والمبلغ والحالة ويمنع تكرار Transaction ID. عند نجاح التحقق يسجّل الحدث ويحوّل الطلب إلى `processing` و`payment_status = captured`. لا يسلّم المتجر الأكواد أو ينفذ الشحن تلقائيًا: يراجع المدير الطلب المدفوع ويكمله من لوحة الإدارة؛ ويجب تسجيل ملاحظة للشحن المباشر أو الخدمة اليدوية.

## حالة فرع المراجعة

- يعمل التغيير على `review/digital-atlos-launch` فوق فرع ميزة الدفع الحالي، وليس على `main`.
- لم تُدمج التغييرات ولم تُنشر Edge Functions المعدلة إلى Supabase الإنتاجية.
- لم تُطبّق أي migration جديدة، ولم يُغيّر المخزون أو الأسعار.
- يبقى `store_settings.checkout_enabled = false` إلى حين المراجعة والتفعيل الصريح.
- لا تظهر منتجات CJ المادية في واجهة العملاء؛ وتبقى أدوات CJ محصورة ببيئة التطوير.
- الدفع اليدوي غير متاح من واجهة العميل في هذه المرحلة. تعرض الواجهة الدولار، وهو نفس أساس حساب ATLOS.
- نجحت اختبارات التوقيع الأربعة واختبارات CORS الأربعة، ونجح TypeScript وVite build بإعدادات Supabase عامة وهمية؛ لم يُنشأ طلب حقيقي ولم تُجرَ معاملة.

## الأسرار وإعداد ATLOS

يجب حفظ `ATLOS_API_SECRET` و`ATLOS_MERCHANT_ID` في **Supabase Edge Function Secrets** فقط. لا تضع السر في GitHub أو Cloudflare Pages أو أي متغير يبدأ بـ`VITE_`. يعيد `checkout-status` معرّف التاجر العام فقط عندما يكون checkout وأسرار الـ webhook مهيأة.

عنوان الإشعار هو:

`https://<project-ref>.supabase.co/functions/v1/atlos-webhook`

يُسجّل هذا العنوان في لوحة التاجر. الأسرار التي زوّد بها المالك لم تُضبط على الإنتاج بعد.

## ما يلزم قبل فتح الدفع

1. مراجعة فرع/معاينة Cloudflare واعتماد الواجهة والتدفق، دون دمج إلى `main` قبل الموافقة.
2. الحصول من ATLOS على تأكيد مكتوب لبيئة Sandbox أو حساب اختبار ووسيلة التحقق من إشعار اختبار. لم يظهر في التوثيق العام الذي راجعناه Sandbox أو بيانات اختبار؛ لا تستخدم دفعة حقيقية للاختبار.
3. بعد المراجعة، إضافة أسرار ATLOS إلى Edge Function Secrets وتسجيل عنوان الـ webhook أعلاه في لوحة التاجر، من دون وضع السر في المتصفح أو Cloudflare Pages.
4. في بيئة اختبار منفصلة، التحقق من الدفع الصحيح ومنع الدفع عند التوقيع الخاطئ، وتكرار Transaction ID، وطلب غير معروف، أو تاجر/مبلغ/عملة/حالة غير مطابقة؛ واختبار الحجز والتحرير والتسليم الرقمي دون استخدام مخزون الإنتاج أو إجراء عملية مالية حقيقية.
5. تنفيذ مصالحة دورية للمعاملات عبر `Transaction/List` قبل الإطلاق العام؛ هذه المهمة المجدولة غير مضافة بعد، وتوصي بها وثائق ATLOS.
6. بعد اجتياز الاختبارات والمراجعة، يكون التغيير الإنتاجي النهائي هو نشر الواجهة ووظائف Edge المعدلة، ثم فتح `store_settings.checkout_enabled`. لا تُفتح هذه القيمة إلا بعد موافقة المالك الصريحة على خطوة الإنتاج المحددة.

## ملاحظات أخرى

تسجيل البريد/Google موجود في التطبيق مع `redirectTo` إلى أصل الصفحة، لكن إعداد Supabase Auth للـ Site URL وRedirect URLs ومزوّد Google لم يُؤكّد من واجهة المشروع في هذه المراجعة، لذلك لم نُجرِ تسجيلًا حقيقيًا. استعادة كلمة المرور وTelegram وتذاكر الدعم والعملات المحلية/تبديل اللغة الإنجليزية ورفع صور المنتج إلى Storage ليست ضمن الميزات الجاهزة لهذا الإطلاق؛ لا تعرضها الواجهة الإنتاجية كميزات عاملة.
